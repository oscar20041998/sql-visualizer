# Database AI Assistant 🗄️

A free-form chat page for general database questions — SQL across dialects, schema design, indexing, performance, transactions, and more — optionally grounded in excerpts from the official SQL Server, MySQL, PostgreSQL, and Oracle manuals.

## Where to find it

Open **Database AI Assistant** from the sidebar (`/database-ai-assistant`). Unlike the AI SQL Explainer, this page does not require an analyzed query — ask anything database-related at any time.

## How it works

1. Type a question or pick one of the starter suggestions (schema design, indexing, JOIN optimization, NoSQL vs. SQL, ACID transactions, pagination).
2. The answer is generated by whichever provider is configured in **Settings → AI Model Configuration** (Ollama, OpenAI, Anthropic, or Gemini).
3. After each answer, four fresh follow-up questions are suggested as chips, so the conversation keeps offering new directions instead of repeating the same starters.
4. Use **New chat** to clear the conversation and start over.

## Grounding in official database manuals (RAG)

Alongside the model's own general knowledge, every question is also matched against a local knowledge base of ~80,000 excerpts chunked from the official SQL Server, MySQL, PostgreSQL, and Oracle documentation.

- The question is embedded locally via Ollama and compared against the manual excerpts; the closest matches (when relevant enough) are handed to the model as reference material, with instructions to prefer and cite them.
- When grounding was used, the answer shows a **Sources** row underneath, naming which database's manual (and section/page, where available) it drew from.
- If nothing in the manuals is close enough to the question, the assistant simply answers from its general knowledge — there is no error and nothing is shown in the Sources row.

This retrieval step always uses a local Ollama model, **independent of which provider generates the final answer**. That means grounding can work even if your chat provider is OpenAI, Anthropic, or Gemini, as long as Ollama is running locally with the required embedding model.

## Enabling grounding

Grounding is optional and degrades gracefully — the assistant works without it, just without Sources.

1. Install and run Ollama (see [Install and Use Ollama](../smart-editor-ai-assistant/OLLAMA_SETUP_AND_USAGE.md)).
2. Pull the embedding model used to build the manual index:
   ```bash
   ollama pull all-minilm
   ```
3. Build the local knowledge index once (requires the raw manual-chunk dump; ask a maintainer if `src/lib/ai/document_chunks.json` is not already present):
   ```bash
   npm run build:database-knowledge-index
   ```
   This re-embeds every chunk through Ollama and writes `src/lib/ai/data/databaseKnowledge.*` — a one-time step (~20-30 minutes for ~80,000 chunks), not something rebuilt on every request. Rerun it only if the source dump changes.

## Configuration notes

- Ollama's base URL comes from **Settings → AI Model Configuration**; the retrieval step reuses that same address.
- The knowledge index files are generated locally and are not committed to the repository (too large); each machine that wants grounding needs to run the build step once.
- For query-specific questions about SQL you have already written, use the **AI SQL Explainer** in the Smart SQL Editor instead — this assistant does not read your current query or schema.
